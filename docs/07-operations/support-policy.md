# Support Policy (Draft)

- Channels: in-product (linked to relevant Mistake/finding context where
  possible), email, and — for Enterprise tier — a named contact.
- Severity definitions should reuse the product's own severity rubric
  language (Critical/High/Medium/Low, see
  [PRD.md § Issue severity mentions](../01-product/PRD.md)) so support
  and product severity aren't two separate vocabularies customers have
  to learn.
- Response targets: see [sla.md](./sla.md).
- Escalation path for security-relevant reports specifically routes to
  [incident-response-plan.md](../03-security/incident-response-plan.md),
  not general support triage.
